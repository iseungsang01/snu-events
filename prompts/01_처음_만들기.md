# 요청: "이번 주 서울대 행사 한눈에" 웹페이지

서울대 홈페이지의 SNU 캘린더(https://www.snu.ac.kr/snunow/events)는 행사가 등록순으로 한 페이지에 몇 건씩만 나와서,
이번 주에 뭐가 있는지 보려면 수십 페이지를 넘겨야 해. 이걸 한 화면에서 날짜순으로 보고 종류별로 거를 수 있는
정적 웹페이지를 만들어 줘. GitHub Pages(`docs/` 폴더)로 배포할 거야.

참고 자료는 `reference/` 에 있어.
- `snu_events.py`, `_retry.py`: 내가 다른 프로젝트에서 쓰던 수집기. 목록·상세 파싱 방식은 이대로 맞아.
- `sample_raw_events.json`: 그 수집기가 2026-10-26에 받은 실제 결과 101건(idx, title, period, begin, end, desc, content).

## 만들 것

1. `scripts/fetch_events.py`
   - reference 수집기에서 필요한 부분만 옮겨 독립 실행되게 해 줘(requests, beautifulsoup4만 사용). 요청 사이 간격은 그대로 둬.
   - 끝난 지 7일이 넘은 행사는 버리고 `docs/events.json` 으로 저장: `fetched_at`, `events[]`.
   - 행사마다 `id, title, begin, end, summary(120자 이내), url(원문 링크), type, place, time` 을 넣어 줘.
   - `type` 은 제목과 본문으로 정하는 규칙 분류: 공연 / 전시 / 대회·공모 / 특강·세미나 / 모집·안내 / 기타.
   - `place`, `time` 은 본문에 "장소:", "일시:", "101동 210호", "14:00" 같은 표기가 있을 때만 뽑고, 없으면 빈 문자열. 추측해서 채우지 마.
   - `--from-sample reference/sample_raw_events.json` 옵션으로 네트워크 없이도 같은 변환을 돌릴 수 있게 해 줘.
2. `docs/index.html` (한 파일, 외부 라이브러리 없이)
   - 위쪽에 기간 탭: 오늘 / 이번 주 / 다음 주 / 이번 달 / 전체. 기본은 이번 주. 날짜는 Asia/Seoul 기준.
   - 종류 칩(여러 개 선택), 제목·내용 검색창.
   - 날짜별로 묶은 목록. 며칠짜리 행사(전시 등)는 "진행 중"으로 따로 묶어 줘.
   - 카드에는 종류, 제목, 날짜·시간, 장소, 요약 한 줄, 원문 링크.
   - 맨 아래에 데이터 출처(SNU 캘린더)와 마지막 갱신 시각, "행사 정보는 원문이 기준"이라는 안내.
   - 폰 화면에서도 보기 좋게, 다크 모드 지원.
3. `tests/test_fetch_events.py`: 날짜 파싱, 종류 분류, 장소·시간 추출, 지난 행사 제외를 샘플 데이터로 검증하는 pytest.
4. `.github/workflows/update.yml`: 매일 한 번(한국 시간 오전 6시) 수집기를 돌려 `docs/events.json` 이 바뀌면 커밋.
5. `README.md`: 무엇인지, 로컬에서 돌리는 법, 데이터 출처를 짧게.

## 지켜 줘

- 로그인 없이 열리는 공개 목록만 읽어. 개인정보(담당자 이름·전화·이메일)는 summary 에 넣지 마.
- `reference/`, `prompts/` 는 건드리지 마.
- 다 만들면 `--from-sample` 로 `docs/events.json` 을 실제로 만들고 pytest 를 돌려서 결과를 알려 줘.
